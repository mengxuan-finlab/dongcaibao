# Financial reports on the Node backend

## Deployment

1. Execute `server/sql/financial-report-jobs.sql` in the Supabase project used by
   `tracked_stocks` and this site's authentication. It adds a service-only durable
   job table and four RPCs; it does not delete existing reports or guest claims.
   Existing installations must allow the text statuses `financial_queued`,
   `financial_running`, and `financial_error` in `tracked_stocks.status`.
2. Deploy the Node backend on Render with the existing `FMP_API_KEY`,
   `GEMINI_API_KEY`, `SUPABASE_URL`, and `SUPABASE_SERVICE_ROLE_KEY`. The service
   key and URL must belong to that same project. The current `GEMINI_MODEL` and
   `GEMINI_FALLBACK_MODEL` settings are reused; no new model name is assumed.
3. Publish `client/financial_statements.html` on Vercel. Add a US symbol or press
   Start on an older pending report. Both tabs are generated by one backend job.
4. This repository's `cron_job.yml` no longer invokes `official.py`; Taiwan's
   `tw_financial.py` schedule remains enabled. In the separate `HIMS_chart`
   repository, remove `python script/updated_report.py` from the workflow's run
   steps (keep `tw_updated_report.py`). Do not stop the entire workflow if Taiwan
   reports still depend on it. Drain/stop old US workflow runs before migrating
   existing `review` rows to avoid a late legacy write overwriting the new report.
   That separate repository is not modified by this change.

There is no SerpApi request in the new financial-report pipeline. Do not remove
`SERPAPI_KEY` from Render globally: `/api/news-radar` still needs it.
The old Python files remain available for reference/rollback, not as a second
worker for the same US reports. Once deployed, this flow does not require Python
on Render. The external `hims-chart.vercel.app` chart viewer is still used; its
`report_json.data/ai` contract is preserved.

## Execution and Failure Behavior

- The browser still creates a tracked row with its own Supabase identity and
  RLS, preserving the one-lifetime-report guest trigger. The backend accepts only
  a tracking ID and authenticates the caller before invoking the owner-checked
  admission RPC. It never trusts a user ID supplied in the request body.
- The database serializes admission per user, deduplicates user/symbol jobs and
  globally leases at most two concurrent jobs. Queue capacity is 24. Each worker
  runs one job at a time, checking every five seconds while busy and backing off
  for 30 seconds when idle. A new request wakes it immediately. Requests return 202;
  the browser polls every five seconds
  without reloading completed chart iframes on each poll.
- Leases last four minutes; job execution has a 180-second client-side deadline.
  On restart, a different worker reclaims expired leases. Unique fencing tokens
  stop the old worker from writing after replacement. Up to three claims recover
  interrupted work; failed jobs require an explicit retry, at least one minute
  apart. There are three attempts per user/symbol/day and 20 per user/day, using
  Asia/Taipei calendar days; admission and claim both enforce the daily cap. Browser
  closure does not cancel queued work. Source metadata absence does not trigger
  retries. A canceled/timed-out upstream request may still incur provider charges.
- Completed results are saved to `tracked_stocks` and the private job table.
  Admission reuses recent results (three-day window), including after a member
  removes/re-adds the same symbol. Existing completed reports remain readable;
  polling/refreshing status does not regenerate or spend AI quota. This is
  per-user reuse, not a global cross-user financial-report cache.
- Both official summary and metric interpretation use one normal Gemini call
  with Google Search and URL Context. At most three calls cover bounded API /
  JSON-validation retries and an optional configured fallback; SDK retries are
  disabled. HTTP 400 gets one schema-free compatibility attempt with the same
  local required-field checks. Every metric field remains mandatory.
- Up to three FMP requests run concurrently. Quarterly income/balance, annual
  cash flow/EPS, annual metrics/ratios and TTM points retain their periods.
  Missing values are omitted rather than converted to zero; zero is valid.
  ROE/ROA become percentages. Annual OCF is joined to debt only at matching dates
  and currency. CapEx uses an absolute numerator. Negative P/E/PEG are omitted.
  Different report currencies fail rather than silently mixing monetary units.
  The legacy external viewer still hardcodes USD monetary labels. Its labels
  must be updated to use `report_json.currency` before offering non-USD reporters
  (including some US-listed ADRs); this migration does not convert currencies.
- FMP selects the filing URL. Backend downloads allow only HTTPS SEC Archives,
  no redirects, 12 seconds, 4 MB. The prompt explicitly labels the bounded extract
  as partial and asks tools to read the corresponding official original / IR
  filing. SEC blocking can still happen; a failed page read is not a full-document
  verification. No read evidence means no invented official summary, but valid
  FMP charts and financial analysis can still complete. The document tab then has
  no official summary. General web-search metadata is not sufficient to label a
  document as read. An issuer-host URL read is evidence of retrieval, not proof
  of sentence-level or quarter-level verification; prompt rules must still align
  company and period. Telemetry records sources, searches and URL reads.
- Real sources and returned Google Search Suggestions are displayed; suggestions
  use a script-disabled sandbox. The official Markdown deck strips HTML tags and
  attributes outside a formatting allowlist. New AI text is HTML-escaped for the
  legacy external chart viewer. Session-bearing chart links accept only that
  viewer's HTTPS origin. Migrating the iframe's legacy token-in-URL integration
  to a same-origin renderer is separate future work.

## Verification Before Public Use

Use a member and an anonymous session. Check both report tabs, duplicate clicks,
refresh, closing/reopening, invalid symbols, FMP denial, AI 429/503/timeout,
missing source metadata, failed-task retry and deleting a running report. Use
another account's tracking ID and verify a 404, with no job created. Restart
Render during a task and confirm reclaim after lease expiry, not immediate
double-generation. Check logs for `[財報生成]`; never paste API keys or tokens.

The migration and worker are tested with mocks/local PostgreSQL-compatible
fixtures. Live FMP/Google/Render and the production Supabase schema still need
deployment verification; 1-3 minutes is a target, not a guarantee.
